## 4. Driving
- Input: standard movement keys while attached to the slave; the local controller is created by `FUN_390c1b80` (log "activating local vehicle movement controller") -> `FUN_390abe10` (0x1a0 object, vtable 0x399a316c). Its per-frame `FUN_390acee0` dispatches: physics wheeled vehicle (`FUN_3909c660`, `PE_WHEELEDVEHICLE`, "wheeled vehicle warped from.. resetting") when the unit's wheeled flag (+0x2a0) is set; else `FUN_390a3de0` when `desc+5` flag is set (kinematic integrator with 3 euler rates, used for non-wheeled flying/boat-like bodies); else `FUN_390ac300` -> CryPhysics (external thunk 0x3a9c33fa, not resolvable). The wagon has `use_wheeled_vehicle_simulation f`, so it takes the generic path whose formulas live in CryPhysics, not x2game. [R dispatch, ? exact formulas]
- Numbers: `velocity 4.0` (m/s max, matches Summon Info "Move Speed"), `angVel 0.4` (rad/s), linear and rotational inertia 0.4/0.4 and 0.2/0.2 (acceleration time constants, [I]). Reverse speed factor for `wheeled_vehicle_gear_speed_ratio_reverse -0.5` is only for wheeled sims. [R values]

## 6. Bevy comparison (D:/aaemu-client/AABevy1.2)
Reviewed: `crates/aa-client/src/ingame/vehicle.rs`, `ingame/data.rs`, `ingame/ground_target.rs`, `hud/vehicles.rs`, `docs/aa-client-parity.md` row "Pets, slaves and transport".

1. **Boarding is automatic in Bevy, interaction-based in the original.** `vehicle.rs:96-186` auto-sends `CSBindSlave` once when an own land vehicle is within 30 m ("one-shot auto-board"); comment at `vehicle.rs:80-84` claims the original has no board button. Original: bind only through target interaction (`FUN_393be280 -> FUN_39362f50 -> CSBindSlave`), no auto-bind after `SCSlaveCreated`. Fix: remove the land auto-board, bind on interaction with the slave target (right click / interact key), with the original prechecks (dead, busy, already bound, range) and error texts.
2. **No wheels.** Bevy draws only the body `.chr` (`data.rs:333-345`). Original attaches wheel cgf models to bones `wheel0/1` (`vehicle_models.wheel`) and `wheel_type20/21` (`wheel2`) and spins them. Fix: parse bone names from the `.chr`, spawn the 4 cgf models, rotate by received/own wheel speeds with radius = half the wheel bbox extent.
3. **`vehicle_models.wheel` misread as a count.** `data.rs:467-478` reads `v.wheel` (a cgf path, TEXT) as an integer, which fails and falls back to 2, so `VehicleMove.wheelCount` is always 2. Original writes the actual number of wheel bones. Wagon: 4 (2+2). Fix: count the `wheelN` and `wheel_typeN` bones.
4. **Helm/driver detail missing.** Original shows `transfers_trailer_a_hlems.cgf` at `$helms`, IK on `$IK_Grip_L/R`, `Bone_spindle` follows steering. Bevy: seat pose only (`mount.rs`), no helm, no grip IK.
5. **Cargo crates absent.** Original: four `doodad 3446` interaction doodads at `$cannon0..3` (positions listed above), swapping model per loaded pack. Bevy draws doodads attached to a slave in the parent frame (parity row) but the vehicle spawn path does not bind `slave_doodad_bindings` to attach points of the prefab, verify `models` -> `slave_doodad_bindings` coverage for slave 60.
6. **Summon placement.** `ground_target.rs:12,99,544` only gives ship items the water reticle; "a mount summon keeps the plain unit cast" and land vehicles are not described. Original (SlaveLocator): cursor ray, wheel rotation, OBB intersection validity, red `housing_build_invalid` material, for kinds 2/3 (land). Verify and add the locator for land vehicle items [I].
7. **Summon Info opens on boarding in Bevy** (`hud/vehicles.rs:463-471`); original opens it only by the Info key binding (`SHOW_SLAVE_INFO` only from stub 0x392043d0) and hides it when the bar has 0 skills. Fix: bind the "Open Pet Details" key to `SHOW_SLAVE_INFO`, drop the boarding trigger.
8. **Unbind guard.** Original refuses `CSDiscardSlave` above 5 m/s (speed² > 25). Bevy `vehicle.rs:98-111` sends unbind at any speed (the wagon is below the limit, cars at 15 m/s are not).
9. **Driving model.** Bevy: arcade accel 8, brake 14 (`vehicle.rs:15-17`), speed scale `velocity`, turn `angVel`, reverse half speed, heading follows the camera. Original uses CryPhysics bodies with `lin_inertia`, `rot_inertia`, `max_climb_ang 45` (not implemented), no camera-follow heading known [?]. Roll/pitch always 0 in Bevy (`vehicle.rs:23-26`), original sends the physical quaternion. Open: needs CryPhysics oracle (already listed open in the parity doc).
10. **Rendering of slave nameplate/etc.** `models.show_name_tag t`, `name_tag_offset 3.0` for model 1008; check Bevy uses 3.0 rather than a default height for the "Farm Wagon" tag (the screenshot tag sits above the wagon).
