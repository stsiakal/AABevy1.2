# x2game.dll survey r3: `0x394bec40` .. `0x397135d0`

Branch `docs/x2game-survey-3` (from client `main`). Read-only breadth-first classification of the
shipped 1.2 `x2game.dll` functions in this address range for the Bevy parity programme. Method
follows `../port-engine-survey/core.md` sections 0 and "Module totals": group by the binary's own
strings, call clusters and address neighbourhoods, then judge against the existing maps and ports.

Sources (image base `0x38ff0000`):

* `D:/aa-re/client12/out-x2game/funcs.csv` (12,935 functions / 2,281,681 code bytes in range)
* `x2game.dll.c` (decompile, sliced only; never read whole)
* `calls.tsv`, `strings-xrefs.tsv`, `strings.txt`, `imports.txt`, `exports.txt`
* existing maps `docs/research/port-*/MAP.md` and `docs/research/port-program.md`
* ports/implementations `crates/aa-client/src/port/**`, `crates/aa-client/src/hud/**`, `crates/aa-*`
* native Lua API inventory `docs/ui-api.md`, `data/ui-api.json`

Tags: **[R]** read from the binary/decompile, **[I]** inferred from data or an unread branch.

## How to read the statuses

| status | meaning here |
|---|---|
| MAPPED | an existing `docs/research/port-*/MAP.md` covers the area (cited) |
| PORTED | at least one live address of the area is in `crates/aa-client/src/port/**` (cited) |
| COVERED | an existing crate implements the area, but 1:1 equality is not proven (crate named) |
| TO-PORT | client game logic that decides what the player sees/does, and no map covers it |
| OUT | not worth porting: telemetry, anti-cheat, publisher/tooling, engine allocator glue, or generated C++ data-model/STL code |
| UNKNOWN | could not classify |

DB intervals are split into **loaders** (note A) and **model** (note B), so the two statuses do not
hide each other.

**Note A - DB loaders.** Functions that call the in-binary SQLite wrappers (`0x3955b3d0`
prepare, `0x3955fb10` step, `0x3953a390` column, `0x395519b0` finalize, `0x395338f0` errmsg,
`0x3953a480` text) or contain an `SQL`/`function=Load*` literal. 454 functions / 223.5 KB from
`0x39571fb0` to `0x39713460`. They map `compact.sqlite3` tables to descriptor objects. The port
reads the same DB through rusqlite in `crates/aa-client/src/hud/data.rs`, `aa-anim/src/db.rs`,
`aa-audio/src/packs.rs` (and smaller readers elsewhere), so the data-access area is covered, but
the per-table loader code is not re-implemented 1:1 and parity is not proven. **[R]** for the SQL
text and helper calls; **[I]** for the coverage claim.

**Note B - DB model.** The remaining ~1.31 MB (1336 KB) of the DB region is generated C++
descriptor code:
constructors/destructors, copy/clone, vtable setup, node alloc/erase, vector/sort helpers and
row serializers. Sampled functions at `0x3957db10` (vector alloc), `0x395823d0` (map erase),
`0x39590080` (descriptor serializer), `0x395c0020` (vector destructor), `0x3962d580` (copy),
`0x39630010`/`39680050` (heap sort), `0x396e0020` (array alloc), `0x39700040` (vector copy);
strings `invalid map/set<T> iterator`, `list<T> too long`, `_Orphan_all`, `_Xlength_error`,
`vector<T> too long`; callers are the loaders above. No gameplay strings. It is out of scope
because Rust structs + std containers replace it, not because it is dead in the original.
**[R]** for the samples/strings, **[I]** for the residual unlabelled leaves.

## Client game logic that looks uncovered

Beyond the three TO-PORT rows, these areas are implemented by crates but have **no `MAP.md`**, so
their parity is unproven and they are the first places to diff against reference captures:

* **X2Chat** (39500000, 169 fns / 25.5 KB): `GetChatCommands` and `UpdateChatTabFilter` have no
  name match in any crate (2 of 29 methods). The rest is `hud/chat.rs`.
* **Crafting** (394d24d0, 163 fns / 36.1 KB + 394dbe90, 39 fns / 3.1 KB): `hud/crafting/*` is a
  rewrite, not a 1:1 port; `re-crafting.md` is RE notes, not a MAP.
* **Auction/trade messages** (394dcef0, 115 fns / 12.7 KB) and **trade UI** (394fdcd0, 30 fns /
  6.1 KB): `hud/auction.rs`, `hud/trade.rs`, again no MAP.
* **Item getters/duration** (394f0000, 67 fns / 20.2 KB) and **item use/equip** (394e06a0, 112 fns /
  16.3 KB): partly MAPPED, the rest is `hud/items.rs`/`tips.rs`.
* **DB descriptor model** (note B): the port reads only the tables it needs; no client-side
  descriptor object layer exists. This is intentional, but it means table semantics are reproduced
  per feature, not centrally.

## Notes and confidence

* The range is dominated by the client's local game-database layer: SQLite 3.5.6 (294 KB), the
  formula engine (16 KB), the game-data enum tables (20 KB) and the DB loaders/model (1.56 MB).
  The actual Lua-facing game client (X2Unit/X2Util/X2Warp/X2World, craft, item/trade/auction, chat,
  startup) is the first 319 KB.
* `0x394bec40` is exactly the second stat-bind variant (`UnitModifierInfo`); the range starts in
  the middle of the `ScriptBindUnit` Lua group, so the sibling `UnitInfo` body at `0x394bdc10`
  (outside this range) is not counted here.
* SQLite and the formula engine are the only large blocks with a clean, single-crate replacement;
  the DB model classification is the main judgement call (note B).
* No client, server or live stack was started for this survey; all claims come from the binary
  exports and the repo sources. No UNKNOWN functions and no line-by-line TO-PORT beyond the three
  X2 native groups were found.
