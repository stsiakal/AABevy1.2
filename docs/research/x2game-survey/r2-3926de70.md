# x2game.dll survey: range r2-3926de70 (0x3926de70 .. 0x394bec40)

Read-only breadth survey of the original 1.2 `x2game.dll`, range **r2-3926de70**. It classifies
every `funcs.csv` row whose start VA is in the range into one area, using the same method as
`docs/research/port-engine-survey/core.md` section 0. Derived **only** from the shipped binary and
its decompile; the published CRYENGINE source was not used. No client was run for this survey.

Sources (all read-only):

* `D:/aa-re/client12/out-x2game/funcs.csv` - function extents/sizes; `x2game.dll.c` - decompile;
  `_index.txt` - decompile char offsets; `calls.tsv`; `strings.txt`; `strings-xrefs.tsv`;
  `imports.txt`/`exports.txt`.
* Existing maps, linked not repeated: `docs/research/port-*/MAP.md` (movement, movement-extra,
  mount-anim, combat, engine-combat, interaction, vehicles, housing, formulas, flowgraph, portals,
  engine-ai, engine-core-rest, engine-movie) and `docs/research/port-program.md`.
* Crates: `crates/aa-client/src/port/**` (line ports), `aa-ui`, `aa-net`, `aa-world`, `aa-cry`,
  `aa-fx`, `aa-audio`, `aa-anim`, `aa-pak`; evidence docs `docs/aa-*.md`, `docs/research/re-*.md`.

Tags: **[R]** read in the binary/decompile, **[I]** inferred from strings/xrefs/neighbourhood.
Sizes are `funcs.csv` `size` code bytes; KB = 1024 B. "Runtime" = reached by the shipped client
(UI/login/game), not that the area is correct in the Bevy client.

**Method.** Areas are address bands aligned on the binary's own profiler/class strings
(`X2::GameClient::...`), Lua-binding method names, cvar/packet/file names and call clusters. The
1.2 image is LTCG-linked: classes are mostly contiguous but some helpers are reordered, and only
**1,291 of 10,883 functions (11.9%) carry a direct string xref**, so an unlabelled body is assigned
to the surrounding band as `core.md` does. The classification is therefore approximate at function
level, exact at range/status totals level. Per-row function/KB figures come from the script, not
from manual counting.

**Range totals (from `funcs.csv`): 10,883 functions, 2,275,484 bytes = 2,222.2 KB.**

### How the statuses were assigned

* **MAPPED** rows are areas an existing `port-*/MAP.md` names and sizes at class level: housing
  (`port-housing`), mate/mount (`port-mount-anim`), slave/transfer (`port-vehicles`), ClientUnit
  (`port-engine-combat` + `port-mount-anim` + `port-movement`), buff (`port-engine-combat`),
  doodad use (`port-interaction`), projectile (`port-engine-combat`). MAPs cite only 221 function
  addresses in this range, so these are class/band claims, not per-function citations.
* **PORTED** rows are areas whose key functions are literally cited in
  `crates/aa-client/src/port/**`: housing (`port/housing`), vehicles (`port/vehicles`), combat
  timeline/bar/interaction (`port/combat`, `port/interaction`), formulas (`port/formulas`).
* **COVERED** rows are implemented by a crate/library (aa-ui, aa-client, aa-net, aa-world/aa-cry,
  aa-fx, aa-audio, aa-anim), but not by a line-by-line map/port and **not proven equal**. The two
  biggest are the native X2* Lua API bindings (2,041 fns / 497.0 KB, `0x39435c00`) answered by
  aa-ui, and the UI toolkit (UI bands from `0x3926de70` to `0x392cde70` plus the quest/social
  windows), which `aa-ui` reimplements while running the original Lua bytecode.
* **OUT** rows (140 fns / 28.7 KB) are the embedded Awesomium browser (`awe_webview_load_html`
  [R], `0x392cde70`), the web upload/diary block (`WebFileTransfer`, `cl_web_session_key` [R],
  `0x39309bf0`), and the ScriptBindUnit methods whose own string says they are unsupported on the
  client ([R], `0x394b68d0`).

## UNKNOWN: none, and why

Every function fell into a band with class/profiler strings, Lua method names, packet/cvar/file
names, or a residual between two identified bands. **Top UNKNOWN areas: none (0 fns / 0 KB).**
The honest caveat is coverage of *labels*, not of bytes: 9,592 of 10,883 bodies have no direct
string xref and inherit their band from address neighbourhood/call cluster. A function wrongly
ordered by LTCG inside a neighbouring class would be mis-attributed at function level, but the
range and status totals would not change. The bands whose residual has the weakest direct
evidence are the UI window/modal helpers (`0x392d3e40`, 428 fns / 66.4 KB) and the ScriptBind
registration glue (`0x39435c00`, 2,041 fns / 497.0 KB); both are dominated by aa-ui coverage.

## Partial implementations worth a follow-up (all COVERED, not TO-PORT)

* **Options/UI toolkit persistence** - storage format, restart-option reporting, `Reset`
  semantics and renderer-less quality options are open in `docs/research/re-uitoolkit.md`
  section 5 gaps 4-8 (`option.g`/LevelDB/`hotkey.g` native formats vs Bevy `settings.json`);
  the area above is COVERED by aa-ui/aa-client but not equal.
* **CharacterCustomizer** - `docs/research/equipment-attach.md` says the native dressing/cut
  system was decompiled without full analysis; aa-anim has cut lists/dye/costume behaviour and
  aa-client assembles equipment, so this is a reimplementation, not a port.
* **ClientPlotMan** - the script's plot/skill-motion model lives in `aa-client` (`ingame/combat`,
  `ingame/skill_motion`) with no MAP; a MAP would make the 24 KB band provable.
* **Battlefield/InstantGame and quest context** - aa-client/aa-net implement the windows and
  packets; no MAP covers the x2game side of the 93 KB band.
* **Web browser** - OUT: `awe_webview_*` [R]. If the in-game browser (help/wiki/diary) ever
  becomes parity scope, this 22.7 KB block is new work and the only genuinely unimplemented
  player-visible feature in the range.

## Script

`tools/x2game_survey/survey_r2.py` (stdlib only, run with `python -I`):

```text
python -I tools/x2game_survey/survey_r2.py summary
python -I tools/x2game_survey/survey_r2.py anchors
python -I tools/x2game_survey/survey_r2.py --lo 0x3938b000 --hi 0x39396000 dump
python -I tools/x2game_survey/survey_r2.py func 0x392a8ac0
python -I tools/x2game_survey/survey_r2.py decomp 0x392cebf0 --lines 30
python -I tools/x2game_survey/survey_r2.py coverage --list
python -I tools/x2game_survey/survey_r2.py areas tools/x2game_survey/areas-r2-3926de70.json
```

`areas-r2-3926de70.json` is the hand-written classification used for the table. Running the last
command reproduces the totals above and asserts that the bands partition the range (it reported
`covered 10883/10883 fns, 2222.2/2222.2 KB; unassigned 0 fns 0.0 KB`).
