## 2. Mounting / dismounting
- Trigger: pet bar command button 2 (`PET_CMD_MOUNT`, hotkey name `PetCommandButton<n>`, pet_view.alb), or Lua `X2Mate:MountMate()` = FUN_390697f0: the current target if it is a mate (FUN_393642f0(targetId)), else own mate. Default key binding not found.
- Eligibility (FUN_3935aa10 / FUN_393642f0): unit kind 5, not dead; player not attached, no stun-like flags; **distance² <= 625 (25 m)** else error with detail 0x205; shared **2000 ms** cooldown (`_DAT_3a169944`, "1999 < dt"); LOS raycast mate<->player (FUN_3909ac60) blocked -> system message 0x6b `mate_cannot_mount_blocked`. Other ids: 0x69 hire, 0x6a spawn while corpse, 0x6c spawn no space, 0x6d repair while corpse, 0x6e dead, 0x6f resurrected.
- **No immediate attach.** A "MountHorse Controller" (FUN_390a5f00, update FUN_390aaf30, 10 s lifetime) auto-walks the player to an approach point at the mate's side (FUN_390aa730; arrival tolerance 0.8 m horizontally, -1.5..2.5 vertically; speed halved inside 1.5 m; any movement input cancels). Only when within **3 m (dist² < 9.0)** FUN_3909b070 sends `CSMountMate` 0xa7 {tl_id u16, attach point u8 (1 driver, 2 passenger), reason u8}, then waits 2 s for the server.
- **reason byte = entry side**, FUN_3909ae90 (arg = the mate unit): d = normalize(matePos - playerPos), f = the **mate's** forward (from its quaternion), dot = d.f. dot >= 0.96 -> 3 (back; 1 if passenger seat occupied); dot < -0.96 -> 4 (front; 1 if driver seat occupied); between: cross = d.y*f.x - d.x*f.y, `cross >= 0 ? 2 : 1` (2 = right, 1 = left, **no occupancy override**).
- Server `SCUnitAttached` 0x?? {child, parent, point, reason}: handler FUN_391d49d0 -> FUN_39362770 (waits for the parent to exist, retries via FUN_39364d40) -> Unit::AttachTo FUN_390b3f10 -> FUN_390e16b0 -> "On Attaching" FUN_390eb520, which sets the rider AG inputs `Vehicle` = mount pose name and `VehicleSeat` = reason (2/3/4 stay, anything else -> 1) via FUN_39153b60; pose names FUN_39571f10: 1 horse, 2 lion, 3 bear, 4 wildboar, 5 submarine, 6 smallboat, 7 coupleduckship, 8 speedcar, 9 elephant, 10 pangolin (models.mount_pose_id, 0 -> treated as horse). FUN_390e96a0 binds the rider to the mount skeleton bone.
- **Attach bone**: `model_bindings(owner_type Model, owner_id 450)` -> attach points 1 and 2 -> `model_attach_point_strings`: 1 = actor `bone_spine_driver` (prefab `$driver`), 2 = `bone_spine_passenger` (`$passenger0`), 3 = `bone_spine_passenger1`. `horse_brown_spot.cdf` declares both as `CA_BONE` attachments. `horse_rein` is false for every row of the DB (no reins).
- **Get-on animation** (rider graph `player_full_body`): `Horse Start` -> `Horse_Enter_l/r/b/f` selected by VehicleSeat 1/2/3/4: `fist_ac_horse_{l,r,b,f}_geton` (all 1.00 s; `fist_ac_{lion,bear}_*` also exist). The clips' Bip01 moves (0,0,0)->(0,1.0,1.888) for l/r and (0,2.0,1.888) for b/f while the pelvis goes from standing (z 0.92) to seated (z 0.09). **Confirmed (cryaction `MovementControlMethod` table 0x30778998): `Horse_Enter_*`, `Horse Start` and `Horse End` use movement control 1 (Entity) for H and V, so the engine applies no clip root motion to the rider entity.** The 1-2 m offsets and the 1.888 m height are skeletal Bip01 pose while the rider is already bound to the mount's seat bone (`bone_spine_driver`); there is no approach-offset code in the clip path. Exit event `BindHorseStirrup` binds the stirrups (below).
- **Rider while seated** (states `Horse_Driver*`, extend `InHorse`, all keyed on `Vehicle=horse`): idle `horse_ba_relaxed_idle` (PseudoSpeed 0..0.1, + `horse_ba_relaxed_idle_rand_1..5` after a 3 s signal); walk `horse_mo_normal_walk_f` (0.15..0.6); run lmg `_FIST_MO_RIDER_HORSE_RUN` (0.7..2; XL14 blend: run f/fl/l/bl/b/br/r/fr, lturn/rturn, uphill/downhill, sprint tier); `_FIST_MO_RIDER_HORSE_IDLETORUN` (transition 0.2 s, leave at stop); `horse_mo_relaxed_runtoidle_f`; jump (`Action=jumpMP01`): `horse_mo_jump_f_start/loop/land`; `horse_em_jump_in_place`; gliding states. Skills use `anims.ride_ub` (empty = not playable mounted) and mounted-attack clips `<weapon>_co_horse_attack_{r,l}_*`, `horse_ac_spur_f` (Breakthrough rider), `horse_co_sk_jousting`, `horse_ba_carrot`.
- **Rider speed source**: FUN_390dcc80 each frame copies `PseudoSpeed` and `RequestedTurnSpeedLZ` from the mount's graph to the rider's graph; if the mount's `Stance` is `swim`, PseudoSpeed = 0 (rider sits idle). So rider pose follows the mount, no packets for the rider.
- **Dismount**: Lua `UnMountMate` FUN_390697b0 -> FUN_39361e80(9) sends `CSUnMountMate` 0xa8 {tl_id, point, reason 9}; refused while buffs 0x2b05/0x2b15 are present or within the 2 s cooldown. Also the dynamic action bar (the F-key bar, FUN_392045f0) gets a **`command_unmount` entry, icon `ui/icon/icon_skill_vehicle03.dds`**, whenever the player is attached to its own mate (FUN_3933b1b0); its callback is FUN_39361e80(9). `SCUnitDetached` -> FUN_391d4a70 -> Unit::DetachFrom FUN_390b4000(reason). The unmount controller (FUN_390a6110; 500 ms for reason 9, else 1000 ms) places the player (FUN_3909b1a0: ~1.5 m to the mate's left, else right, collision-ray checked, else the saddle spot; inferred values) and drives the rider's graph `Horse End`: `fist_ac_horse_l_getoff_start` (0.67 s, root (0,0,0)->(-1.0,0,-1.888)) -> `_loop` -> `_end` (0.83 s), played as the jump pipeline (JumpMain/JumpLoop/JumpEnd in the .ag), i.e. a hop from saddle to ground. Reasons 3/8/0xc and 9/10/0xb/0xd take other paths (state 5 / immediate placement FUN_3909b4a0).
- **Stirrups**: FUN_390cd890 moves the mount's `bone_spine_stirrups_l_01/r_01` onto the rider's `Bip01 L/R Toe0` every frame after `BindHorseStirrup` (flag cleared again on attach/detach, FUN_390cea80). Only matters for saddle/stirrup models.

## 3. Mount (mate) animation
- Graph `actor_models.animation_graph = horse_full_body.xml` (id 206; `.ag` compiled copy carries the same states). Stance `relaxed`. Idle: `fist_ba_relaxed_idle` (PseudoSpeed 0..0.1, `idle_rand` signal after 5 s -> `idle_rand_1..3`). Walk: lmg `fist_mo_normal_walk` (S8_1, PseudoSpeed 0.11..0.7). Run: lmg `fist_mo_normal_run` (XL14, 0.8..3, playback clamp 0.6..2, includes `run_f_lturn/rturn`, uphill/downhill and a sprint tier `fist_mo_normal_sprint_*`). Turn in place: lmg `fist_mo_relaxed_turn` (TSTP: `turn_r`, `idle_stop`, `turn_l` by RequestedTurnSpeedLZ), only while Action idle and PseudoSpeed < 1.5. Start/stop: `fist_mo_relaxed_idletorun` (M2I8, leave at stop) and `fist_mo_relaxed_runtoidle` (playback 1.2). Idle steps `fist_mo_relaxed_step_*` (ISTP). Jump: `fist_mo_jump_{f,b,...}_start/loop/land` driven by `jumpMP01/02` like the player; freefall `fist_mo_jump_f_loop`. Swim: `fist_ba_idle_swim`, `fist_mo_swim_*` (+`_deep` below -1 m water level; PseudoSpeed 0.2..2).
- **PseudoSpeed is a requested urgency, not a speed (confirmed).** Producer crygame `FUN_3906a7f0` writes the graph input from the movement request's pseudoSpeed (0 when the request has none; clamped to min(request, 0.4) when the actor flag word has bit0). x2game `FUN_39404d50` builds the request: 0 idle, 1.0 moving, 0.4 with the walk modifier (flag 0x1000, the walk toggle), 1.5 for move-to-point and auto-move (`FUN_393ba480`). cryaction `FUN_306747f0` zeroes it when the ground speed is under 0.5 m/s (other speeds under 0.2). The bands are the graph XML `<PseudoSpeed min max>` conditions. Open: how a sprint value above 1.0 is produced for a mount outside move-to-point / auto-move. `RequestedTurnSpeedLZ` = change of rotation angle in degrees / dt (cryaction `FUN_30665830`).

## 4. Movement
- Actor model 206: `game_stances` (actor_model_id 206) stance 2 relaxed: normal_speed 1.5, max_speed 9.0; ai walk 1.8, run 9.0; `game_sprint_multiplier 1.5` (13.5 m/s), `game_walk_multiplier 0.2`, strafe 0.133/0.2, backward 0.2, `turn_speed 360`, `game_jump_height 1.3`, `physics_living_gravity 20`, **`game_inertia 4.0`, `game_inertia_accel 11.0`** (most actors: 20.0 / 11.0), radius 1, height 1.
- Rider's client sends `CSMoveUnit` with the **mate's object id** and a UnitMoveType (the server's `on_mate_unit_move` handles it); the rider sends nothing for itself. Other players' mounts are normal unit-movement tracks; riders follow by attachment.

## 6. Gaps in Bevy (`ingame/mount.rs`, `hud/pets/owned.rs`)
1. **Get-on/off animation**: fix: choose `fist_ac_<pose>_<l|r|b|f>_geton` from the attach `reason`, bind the rider to the seat bone at once and play the clip with its skeletal motion; dismount `getoff_start -> loop -> end`, rider bound until the clip ends.
2. **Mount flow**: Bevy sends `CSMountMate` immediately (`owned.rs:441-457`). Original: LOS check, auto-walk to the approach point, send only within 3 m, 10 s controller, 2 s wait.
3. **`mount_reason` wrong** (`owned.rs:406-425`): uses the player's yaw; original uses the mount's forward and `mate - player`, with no occupancy override in the left/right band. It also feeds the animation side for other clients.
4. **Missing `command_unmount` dynamic-bar entry** (F bar) while riding the own mate (`icon_skill_vehicle03`, reason 9). Slaves get `unbind`/`showSlaveInfo` analogues.
5. **Mount locomotion** is the generic creature path (`anim.rs:407-520`): no turn-in-place, idle->run / run->idle, run turn blend, mount jump states, sprint tier for mates, thresholds are m/s (3.9 split) not PseudoSpeed bands (walk 0.11-0.7, run >=0.8).
6. **Rider gaits** (`mount.rs:347-353`): split at 3.0 m/s; original uses PseudoSpeed 0.15-0.6 / >=0.7 of run speed, plus idle->run and run->idle clips, jump states (`horse_mo_jump_f_*`), random idles, swim = idle.
7. **Rider skills**: no `ride_ub` (only `move_ub`), no `<weapon>_co_horse_attack_*`, `horse_ac_spur_f`.
8. **Driven mount physics** (`mount.rs:177-194`): instant speed; original `game_inertia 4`, `accel 11` (semantics inferred).
9. Stirrup IK, `CSRemoveMate` auto-dismiss: absent.
10. Pet frame and bar already run the original Lua; keep the natives aligned with FUN_3906aea0 (`MountMate` 390697f0, `UnMountMate` 390697b0, `CanMount` 3906a440, `GetSpeedInfo` 3906ac40).
