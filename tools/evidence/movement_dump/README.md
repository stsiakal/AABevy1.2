# Movement core dump evidence (W3 recon)

Fresh capture from the hidden original 1.2 client on the `move-golden` lane.
Generated by `tools/movement_dump_probe.py`; do not hand-edit.

## Method

1. Launch the hidden original with the lane client driver (standard
   launcher ticket, slot account), enter the world and stand still.
2. Enumerate the process modules and refuse to continue if an
   anti-cheat module is loaded (XignCode/eEHSvc, nProtect, AhnLab,
   HackShield, GameGuard, TenProtect and similar names).
3. Read the target bytes with `ReadProcessMemory` only. The probe has
   no write/`VirtualProtect`/injection path; the driver is used only
   to launch and to press the UI buttons that reach the world.
4. Compare the live bytes with the shipped packed `x2game.dll`, the
   unpacked `x2game_unpacked.dll`, the raw live image `x2game.dll.a.mem`
   and the shipped `cryaction.dll` at the same RVA.
5. Disassemble the live bytes with capstone in 32-bit mode and follow
   direct `jmp`/`jcc`, `call` edges, push-continuation / push-ret
   dispatchers (pushed constants that the obfuscated functions return
   to) and indirect jumps resolved from those pushes. The SEH handler
   pushed after `push -1` is excluded from continuations.
6. Classify (a) plain x86 after runtime decryption, (b) mutated x86 a
   block follower can linearise, or (c) a VM (table dispatch loop,
   bytecode stream, handler table).
